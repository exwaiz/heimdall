# Pi 패키지 조회 수정

작업 #48·#49는 `readonly`였고 소유자 승인 DB 행은 없었다. 실제 Pi에는 APT/dpkg
기록이 있지만 기존 `:minimal` + 홈 읽기 프로필에서는 세 경로 모두 보이지 않았다.
모델은 `require_escalated`로 재시도했고 브리지의 읽기 모드 정책이 자동 거부했다.
Codex 도구의 `rejected by user` 문구는 실제 사용자 버튼 거부의 증거가 아니다.

모든 프로필에 다음 읽기 규칙을 추가했다. 쓰기·sudo·격리 탈출은 허용하지 않는다.

- `/var/log/apt` — 현재·회전/압축 APT 설치 이력
- 기존 일반 파일 `/var/log/dpkg.log*` — dpkg 이력
- `/var/lib/dpkg/status`, 존재하는 `/var/lib/dpkg/arch` — `dpkg-query -W` 목록 조회

일반 모드에서 `/var` 전체·다른 로그/서비스 데이터·인증은 계속 비공개다.
모델 문맥은 실제 Pi의 제한된 파일 보기임을 설명하고, 패키지 조회에 권한 확대를
요청하지 않도록 안내한다. 이전 스레드에도 매 턴 새 안내를 전달한다.
기존 권한 확대 거부는 유지하되 읽기 모드 자동 차단·미지원 요청의 안내를 구분한다.
일반 승인 실패는 원인을 사용자 거부로 단정하지 않는다. Codex 자체 도구의 원문
오류 문자열은 변경하지 않는다.

검증: `scripts/smoke_package_access.py`로 실제 네이티브 샌드박스의 읽기/쓰기 모드에서
APT/dpkg 읽기 및 `dpkg-query` 성공, 시스템 기록 쓰기·네트워크·인증 읽기 차단을 확인한다.
별도 실제 Codex 스레드에서 APT 기록 읽기 성공, 승인 버튼 없이 완료 및 전용 서버
점유 해제를 확인한다. 테스트는 설치·삭제나 운영 대화 재실행을 하지 않는다.
